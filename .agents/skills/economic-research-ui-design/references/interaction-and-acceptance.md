# Controls and acceptance

Read [shared controls](../../../../frontend/src/components/controls.jsx), [popover placement](../../../../frontend/src/components/popover.js), [entity picker](../../../../frontend/src/components/EntityPicker.jsx), [tabs](../../../../frontend/src/components/Tabs.jsx), [navigation drawer](../../../../frontend/src/components/NavDrawer.jsx) and [request cancellation](../../../../frontend/src/hooks/useApi.js) as applicable.

- Give each control a stable label, state, and visible keyboard focus. Preserve checked state and keyboard focus separately, including the Overview context-series controls. Use the shared SearchableSelect for application-owned dropdowns, including touch year menus, and keep filtering for long lists. Use [segmented controls](../../../../frontend/src/components/charts/ChartControls.jsx) for Line/Bar and Auto/Fixed. In annual history, put both switches after the period controls and before the series selector and active legend. Preserve selections while changing mode or period. Preserve selected-state announcements and Enter or Space activation. For custom listboxes keep active-option scrolling, Escape, focus restoration, touch selection, scrolling, and placement against the visual viewport with the keyboard open. Use comfortable targets around 44 CSS px where possible and check applicable WCAG minimums.
- Keep navigation context visible, including the current tab and filter state. Make drawers/dialogs usable through focus order, Escape, return focus and accessible names. Provide loading, empty, unavailable, degraded, partial and error/retry states. Keep keyboard order aligned with reading order. Verify live announcements without duplicating speech. [W3C combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
- Check 320 and 360 px for stacked controls, long labels, missing states and no page-wide overflow. At 390 and 428 px test touch, long lists, chart inspection and both scroll axes. At 768 and 1024 px test layout transitions, portrait/landscape and zoom. At 1440 px verify full navigation, table/plot alignment and long historical windows. Test short landscape and 200% zoom separately. Record browser, viewport and input method. A resized desktop browser does not establish mobile keyboard or touch behavior.
- For approved browser verification use an isolated fixture and the available browser tooling. Include mobile Safari and Chrome on physical devices where possible, keyboard on desktop, and VoiceOver, TalkBack or NVDA on representative workflows. jsdom tests help verify contracts and interactions but do not establish real layout or platform accessibility. Mark unavailable runs clearly.

## Before and after

1. Capture the existing values, displayed units, selected periods, comparisons, denominators, null reasons, methods, evidence paths, controls and states for representative fixtures. Include a degraded or unavailable case and a coverage-changing case. Keep the baseline in disposable artifacts.
2. Compare the same fixture and selections after work. Every meaningful value, label, year, methodology statement, provenance record, verification route and control remains reachable. Where a functional change was separately authorized, verify the intended difference explicitly.
3. Check hierarchy, contrast, tabular alignment, label clarity, spacing and data density across the width matrix. Exercise pointer, keyboard, touch and screen-reader paths, sticky tables with both scroll axes, virtual keyboard, reduced motion and rapid selection changes. Compare chart and table parity. Verify legend-to-mark parity in both modes, the mixed-axis key, and value/percentage separation in grayscale.
4. Record tested browsers, screenshots or DOM measurements when available, relevant test commands and any blocked coverage. Avoid claiming a visual regression is fixed without exercising the reported interaction in an appropriate environment.
