# Recovery and safe verification

## Current contracts

[Database selection and fallback opening](../../../../backend/src/db/index.js) choose a configured Turso primary or local SQLite. Fallback validates file existence, opens/applies schema initialization and checks observation count. Treat opening through this helper as potentially write-capable. The local initialization path requests WAL. In [the server](../../../../backend/src/server.js), a genuine transport failure can trigger guarded fallback and a bounded replay for an idempotent GET. Recovery is single-flight with cooldown, lock checks and a health confirmation window. The serving handle and provider label must agree, and requests already using an old handle must be able to finish.

Recovery uses retrieval/check timestamps and WDI vintage. Where fallback appears newer, [compareDatasetContent](../../../../backend/src/db/repository.js) can establish equality, otherwise reconciliation can refresh the primary from WDI. This is a separate operation from failover. Summary timestamp order, successful ping, a nonzero row count or equal local version integers cannot prove a usable replacement. Before changing promotion rules, verify comparable coverage, per-series/year provenance and validated content evidence. Keep the last valid handle during inconclusive, interrupted or failed recovery. Never allow silent promotion of incomplete or invalid data. Never build an automatic fallback-to-primary overwrite from a local file.

The driver has bounded transport-oriented read retry. Refresh retry semantics are separate. A write retry requires a fresh verified transaction and known rollback or proven idempotence. Treat an uncertain commit as uncertain until observed through safe evidence. Preserve publication atomicity and lock behavior across retries.

## Fixture workflow

1. Select a copied checkout or disposable work area outside the working database. Use a fresh SQLite fixture seeded from [tracked fixture helpers](../../../../backend/test/helpers/testDb.js) and a stub World Bank source if needed. Verify the exact database paths, environment overrides, and that remote networking and credentials are absent from the test process. Do not load local .env files or attach real main/WAL files.
2. Inspect [test isolation](../../../../backend/test/isolation.js) before running it. The default bootstrap can copy the developer cache and sweep stale test directories, and it has a remote opt-out seam. Provide a disposable target and disable remote paths. Some tests expect the protected cache path relative to the checkout, so use a scratch checkout seeded with fixtures when needed. Build file URLs with proper URL encoding and distinguish OS loopback restrictions from app failures.
3. Use [numerical](../../../../backend/test/numerical.test.js), [transforms](../../../../backend/test/transforms.test.js), [ranking](../../../../backend/test/ranking.test.js) and [Compare universe regression](../../../../backend/test/compareUniverseRegression.test.js) for calculation invariants. Use [runtime failover](../../../../backend/test/runtimeFailover.test.js), [divergent recovery](../../../../backend/test/divergentRecovery.test.js), [refresh failure positions](../../../../backend/test/refreshFailurePositions.test.js) and [dataset state](../../../../backend/test/datasetState.test.js) for publication and recovery. Choose only tests whose isolation is established.
4. Cover healthy primary, missing/corrupt/empty/partial fallback, concurrent failover, equal content with different clocks, same stamps with different observations, different series/year coverage, newer fallback, interrupted refresh, failed reconciliation, and stable recovery. Assert values and provenance, source vintage, coverage, lock and generation before/after, plus what concurrent reads see.
5. Record commands, exit codes, fixture versus live boundaries and unverified claims. A sandbox failure is a verification limitation. A disposable remote Turso branch needs explicit future authorization, scoped credentials and measured protocol/transaction behavior. Do not substitute the newer Turso engine or sync SDK for this checkout's installed client. [Official embedded replica documentation](https://docs.turso.tech/features/embedded-replicas/introduction)
