Consult the installed Client and Transaction types and the [official TypeScript SDK reference](https://docs.turso.tech/sdk/ts/reference) for the libSQL package and transport in use.

## Read and cache changes

- Bind SQL values. Use allowlists for dynamic identifiers and generate IN placeholders separately from data. Preserve eligible-entity joins, missingness, ranking and evidence when reducing projections or batching independent reads.
- The indicator/year/value index supports ranking and time ranges. The observation primary key and explicit country/indicator/year index support country histories. Run [EXPLAIN QUERY PLAN](https://www.sqlite.org/eqp.html) against the exact parameterized query and representative disposable data. Check range constraints, joins and temporary sorts before considering an index. Measure index pages, write overhead and plan stability before adding or consolidating an index.
- [Focus-yearly](../../../../backend/src/services/indiaYearly.js) computes ranks and reads many eligible economies to return one focus economy. For history-only work compare a bounded focus projection with the existing output. Keep the predecessor year for real GDP YoY even when it sits outside the visible window. Reuse fetched data only when country, series, window and generation agree.
- [Years cache](../../../../backend/src/services/yearsCache.js) uses per-handle content identity and derived years metadata, with legacy reads if absent. [Compare cache](../../../../backend/src/services/compareCache.js) uses per-handle bounded storage and generation/signature evidence. Match cache keys to every relevant input, including provenance if it changes the DTO. Verify legacy databases, unchanged refresh, provenance-only change, value or coverage change, concurrent requests and target switches. Keep TTL freshness distinct from content freshness.
- An atomic writer does not make a sequence of independently awaited reads a common snapshot. For multi-query responses and cache insertion, prove a consistent read transaction or recheck the generation and retry safely. A content version is local to its database. Never assume equal version numbers across primary and fallback imply equal content.

## Write path and measurements

- [Ingestion](../../../../backend/src/wb/ingest.js) validates and stages outside the publication transaction. It can spill indicator payloads, skips exact unchanged values, can advance provenance separately, and replaces affected indicator/year slices on change. Driver batches default to 500 rows. Publication couples observations, success evidence and derived dataset state in one commit. Check lock cleanup and rollback at every meaningful failure point.
- For an incremental publish design, prove equality on inserts, updates, deletions, provenance-only changes and incomplete source input. Preserve untouched years and last valid committed data. Validate the source payload before replacing a slice. Reproduce restart and overlapping-read/write cases on disposable data.
- Record fixture source/vintage and dimensions, runtime and engine, target path class, cache state, concurrency, iterations, query calls, returned rows and bytes, p50/p95 and write/transaction/lock or WAL metrics as relevant. Distinguish in-process handler time, HTTP, remote transport and client rendering. A result row count is not rows scanned or billed. A batch reduces round trips but does not by itself establish lower billing.
- Compare before/after output and provenance with identical inputs. A production latency or savings claim requires evidence from the relevant environment. Do not invent improvement percentages. See [SQLite query planning](https://www.sqlite.org/queryplanner.html) and [Turso usage/pricing](https://turso.tech/pricing).
