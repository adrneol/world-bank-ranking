====================================================================
MASTER SAFETY REQUIREMENT — DATASET_STATE
====================================================================

The key proposed optimization is a new authoritative metadata row/table,
currently proposed as:

    dataset_state

This must NOT become a second, independently drifting source of truth.

It is a DERIVED AUTHORITATIVE STATE maintained transactionally from the same
successful database publication that changes observations.

The single most important requirement:

    dataset_state MUST ALWAYS REPRESENT THE SAME COMMITTED GENERATION AS
    observations.

Never allow:

    observations = generation N
    dataset_state = generation N-1

or:

    observations rolled back
    dataset_state remains updated

or:

    dataset_state updated
    observation update fails

====================================================================
DATASET_STATE — EXACT SEMANTICS
====================================================================

Do NOT invent semantics for fields.

Define each field precisely.

At minimum investigate the need for:

    observation_count
    max_fetched_at
    stored_dataset_wb_vintage
    years_json
    content_version
    initialized
    integrity_verified_content_version

Potential fields must be separated semantically.

IMPORTANT:

Do NOT confuse:

    data generation/content version
    successful refresh timestamp
    source World Bank vintage
    stored observation vintage
    integrity verification state

These are different concepts.

------------------------------
content_version
------------------------------

Increment ONLY when observation content changes.

For example:

    inserted observation
    updated observation
    deleted observation

=> content_version changes.

An unchanged successful refresh:

    observation content unchanged

=> content_version MUST remain unchanged.

But:

    lastSuccessAt

still advances.

------------------------------
lastSuccessAt
------------------------------

Continue to be owned by refresh/run metadata according to the current TTL
semantics.

Do NOT move TTL authority into a new approximation.

TTL remains:

    ageHours < ttlHours

with the same strict 24-hour semantics already tested.

------------------------------
stored_dataset_wb_vintage
------------------------------

This must represent the vintage semantics of the ACTUAL STORED observations
used by the application.

Do NOT blindly replace this with the latest World Bank source-run vintage when
the source was checked but observation content did not change.

The audit explicitly identified this distinction as important.

Trace current API semantics and preserve them exactly.

If both source-run vintage and stored-dataset vintage are required, keep them as
separate concepts rather than overwriting one with the other.

------------------------------
observation_count
------------------------------

Must remain EXACT.

Do not use approximate counters.

Do not trust:

    old_count + guessed_delta

unless the delta is formally proven against the actual DELETE/INSERT behavior.

If using delta arithmetic, prove it across:

- changed indicator
- partial range
- deletion
- insertion
- replacement
- rollback

A safer implementation may compute the exact count inside the same O7
transaction when required.

Correctness beats saving one metadata scan.

------------------------------
max_fetched_at
------------------------------

Must equal the current stored dataset's actual maximum fetched_at according to
existing semantics.

Do not approximate it.

Do not use the time a refresh started.

Do not use the time a request completed unless it matches the data semantics.

------------------------------
years_json
------------------------------

This field requires an explicit invariant.

It MUST represent:

1. per-metric available years
2. global available years

The global list MUST be the correct union of the per-metric year sets, not the
year set of whichever indicator was processed last.

Example:

    metric A has 2000
    metric B does not

global must contain 2000.

If metric A loses 2000 during a refresh but metric B still has 2000:

    global must STILL contain 2000.

This must be explicitly tested.

Do not simply derive global years from the current indicator.

INTEGRITY VERIFICATION STATE
====================================================================

The old boot integrity check MUST NOT simply disappear because it is expensive.

Determine exactly where the existing O8/integrity guarantees happen.

Propose one of these only after source audit:

A. integrity is already guaranteed as part of every successful data-changing
   publish

OR

B. an explicit integrity check is performed when content_version changes

OR

C. a persisted:

       integrity_verified_content_version

   proves that this exact content version has passed the required integrity
   gates.

The safest target is:

    content_version = 123
    integrity_verified_content_version = 123

meaning:

    dataset content version 123 has passed required integrity validation.

If:

    content_version changes

then:

    integrity_verified_content_version becomes stale.

Do NOT serve a new content generation as "integrity verified" merely because
the old generation was verified.

Do NOT weaken the O8:

    checked === COUNT(*)

completeness gate.

Do NOT replace exact integrity with sampling.

ATOMIC METADATA UPDATE
====================================================================
