Read-only. No source files were edited. Diagnostic commands run: local DB timing, EXPLAIN QUERY PLAN, local HTTP timing of GET /api/years, file/config inspection, targeted greps. Implementation is explicitly not started.

1. EXECUTIVE SUMMARY
What this project is. A World Bank WDI analysis app: Express 5 backend ingests official WDI observations into SQLite and serves backend-calculated ranks/YoY/movements/comparisons; a React 19 + Vite frontend is display-only. Twenty indicators in eight subjects. Ranking/YoY/denominator math lives in backend/src/domain/ + backend/src/services/; the frontend transports results (frontend/src/api/client.js:7 states this explicitly). This separation is intact — no frontend analytical recalculation was found.

Overall architecture (healthy core, three sick edges):

World Bank WDI API
 → wb/client.js (paginated fetch, retries) + wb/ingest.js (staged publish, locks, TTL)
 → SQLite data/worldbank.db (raw preserved; 33.3 MB, 228,776 obs, 20 indicators)
 → domain/ (ranking, yoy, universe, comparison, growthComparison, transforms, *Movement)
 → services/ (backend-authoritative verification, fail-closed invariants)
 → Express JSON API (server.js, ~30 routes)
 → React frontend (single filters object → effective memo → section fetches)
The three reported problems, in one paragraph each:

/api/years deployed timeout (30 s). Locally the endpoint is fast (measured 458 ms first / 356 ms warm over HTTP; 602 ms / 357 ms at repo level). The handler itself (backend/src/server.js:366-373) is one listAvailableYears() call plus fire-and-forget TTL middleware — it does not await ingestion. The deployed failure is therefore not a slow query on a warm host. The evidence chain points to cold/empty/sleeping-backend boot cost: backend/data/ is git-ignored and no DB file is tracked (git ls-files backend/data = empty), there is no IaC (vercel.json/render.yaml/Dockerfile/etc. all absent), SQLite is a local file (ephemeral on serverless/free-tier disks), and boot() (server.js:1338-1345) performs a blocking full ingest on empty DB (1960→current year × 20 metrics via paginated country/all fetches). Add Render-style sleep/wake (~30–60 s container + Node 22.5 + schema + COUNT(*) + integrity scan), a 24 h TTL background refresh that publishes 228 k rows in one transaction, an N+1 DISTINCT years query, and a frontend that blocks every view behind filtersReady with no AbortController on the years effect — and a 30 s fixed timeout becomes a whole-app outage. Details + measurements in §4.
Focus-country leak (India sticks). There is no single clean source-of-truth bug; there are four stacked mechanisms: (a) an active display hardcode in RankMovement.jsx (r.iso3 === 'IND' at lines 626, 630, 785, 789, 1765, 1769, 1916, 1920 + ~40 "India…" narrative strings) that highlights/labels India even when country=USA — every other movement family correctly uses focusIso/focusName; (b) Compare defaults coupled to focus (App.jsx:324-326: cmpEntityA = country:${country}, cmpEntityB = USA↔CHN swap) so changing focus rewrites Compare's unresolved defaults; (c) IND-omission in share URLs (App.jsx:368: country omitted when IND) combined with fail-closed-to-IND resolution (App.jsx:314-317); (d) dormant country='IND', focusName='India' prop defaults in ~17 section/component signatures (harmless today because App.jsx always passes explicit props, but any direct render/test without props reverts to India). Cache keys are otherwise correct (every depsKey includes ${country} except Compare-main, where the entity spec already encodes country). Full trace in §5.
Analytical views / Compare navigation. The registration itself is clean (single ANALYTICAL_VIEWS array, NavDrawer is a correct accessible dialog, aria-current="page", focus return works). The breakage is in state/URL architecture: no router (no Routes/pushState/popstate listener at all), URL mirroring uses replaceState only (App.jsx:382) so browser Back/Forward changes the URL bar without updating state; rankSub/yoySub tab state is not in the URL (App.jsx:155-156, absent from PARAMS); cmp* params are only serialized when view==='compare' (App.jsx:370-380) so a Compare link opened from another view depends on live state; every view switch remounts <main key={dataVersion:view:country}> (App.jsx:648) destroying local pagination/tab/detail state by design. "Current: Status" is derived from routing state (NavDrawer.jsx:156 renders triggerLabel, which App.jsx:542-546 derives from view) — not a separate bug, but the label and the drawer can only agree when view is correct. Compare-specific: its fetch is correctly focus-independent, but its defaults inherit focus (see above) and its Trajectory panel fans out up to 31 api.observations calls. Details in §6.
Methodology verdict: GDP families flow through the generic ordinal-rank engine with extensive golden protection (perCapitaRegression, comparison oracle sweeps); non-GDP families deliberately diverge (competition ranking, ASC/NEUTRAL directions, signed-domain refusals, four different period dialects, mean-vs-median benchmarks). No invented values, no fake graph data, no frontend math duplication found. The biggest regression hazard is confusing the dialects (ordinal vs competition ranks, [A,B) vs inclusive vs S+1..E periods, positionNumberChange vs placesGained). Details in §7.

4. /api/years FAILURE ANALYSIS
4.1 Exact request path
Browser: api.years()  [frontend/src/api/client.js:138 → get('/api/years',{},options)]
  → App.jsx:181-182  api.years()  (no timeoutMs override → 30000; no signal)
  → GET {base}/api/years
  → Express: CORS → JSON → auto-refresh middleware (server.js:339-351)
  │     maybeAutoRefresh(handle(), …)   // getCacheStatus: COUNT(*) + MAX(fetched_at)
  │                                      // + latest run + lock check; stale/empty →
  │                                      //   fire-and-forget refreshData() + X-Auto-Refresh
  → handler (server.js:366-373): listAvailableYears(handle())
  │     1× global DISTINCT + N× per-metric DISTINCT (N = 20 indicators)
  → 200 { years[66], minYear, maxYear, perMetric{20}, defaults{2000,2025}, methodology }
EXPLAIN QUERY PLAN (measured locally):

Global DISTINCT: SEARCH c USING INDEX idx_countries_is_aggregate → SEARCH o USING INDEX idx_observations_country (country_id=?) → USE TEMP B-TREE FOR DISTINCT. I.e. no covering index on (year) — join + temp-tree distinct over all 228 k rows.
Per-metric DISTINCT: SEARCH o USING INDEX idx_observations_ind_year_value (indicator_id=?) → indexed, fine.
repository.js:524-547 loops listIndicators → listYearsWithData per indicator: 1 + 20 = 21 queries per /api/years call. /api/metadata (server.js:1144) and /api/data-status (server.js:1243) call the same function plus COUNT(*)/MAX(fetched_at), so they share the cost profile.

4.2 Exact frontend timeout path
client.js:45: DEFAULT_REQUEST_TIMEOUT_MS = 30000.
request() (:66-90): creates internal AbortController, arms setTimeout(30000) → aborts with TimeoutError.
catch (:99-107): timeout → ApiError("The backend is taking longer than expected (HTTP GET /api/years exceeded 30000 ms). It may be warming up — retry shortly.", {code:'TIMEOUT'}). This is the exact deployed message.
Years bootstrap (App.jsx:177-196): no signal, no useApi, only a cancelled flag — filter changes/navigation cannot abort it; competing requests pile up.
Failure UX (App.jsx:564-580): Could not load available years: {message} + Retry button (setDataVersion(v=>v+1) refetches years + countries + indicators simultaneously).
Blast radius (App.jsx:436,660-742): filtersReady = !yearsLoading && !yearsError && availableYears.length > 0; every data view (overview/data/rank/movement/yoy/compare/coverage/audit) renders only under filtersReady. A years failure is a whole-app outage, including the Status view's siblings (Status itself renders without filtersReady, but nothing else does).

4.4 Cold/warm/deployed behavior
Local warm (DB present, TTL fresh): ~0.4 s. Healthy.
Deployed cold / empty DB: boot() blocks listen on ensureDataPresent full ingest: fetched range 1959(predecessor)→current year × 20 indicators through country/all pagination, each WB request 30 s timeout × 5 retries (wb/client.js:114,162). Expected duration: minutes, not seconds. During this window every request (or connection refusal, depending on boot phase) exceeds the 30 s frontend bound.
Deployed cold /تریال ephemeral disk: backend/data/ is git-ignored (.gitignore:11-15) and no DB is tracked (git ls-files backend/data empty). Any host with an ephemeral filesystem (Vercel serverless, Render free without persistent disk) starts empty on every deploy/restart/sleep-wake → repeats the full ingest. This is the highest-probability standing cause.
Sleeping backend: free-tier hosts suspend idle containers; wake = container start + Node 22.5 boot + getDb WAL/schema/migration + COUNT(*) + stale-lock check + integrity scan + (if TTL stale) background refresh spawn — easily 10–60 s before Express answers, all inside the frontend's 30 s window. The "warming up — retry shortly" copy assumes exactly this, but the app has no warmup path that answers /api/years from a cheap source while boot finishes.
Every-request cost (not just cold): even warm, each /api/years pays the auto-refresh middleware's getCacheStatus (COUNT(*) + MAX(fetched_at) + run lookup) plus 21 DISTINCT queries; when TTL is stale it additionally spawns a background refresh whose single-transaction publish of ~228 k rows contends on the one shared SQLite handle (WAL helps concurrent reads, but the writer's COMMIT plus the sync DatabaseSync API serializes work on one connection). Concurrent years + metadata + data-status + section fetches queue behind it.
Frontend amplification: Retry bumps dataVersion, refetching years+countries+indicators at once; the years effect has no abort, so rapid retries stack uncancelled 30 s requests; the background data-status watcher (15 s timeout, first check staggered 30 s, App.jsx:446-493) never surfaces errors and does not mitigate.
4.5 Likely root cause (ranked, evidence-backed)
Empty/ephemeral DB → blocking boot ingest on the deployed host (evidence: git-ignored backend/data/, no tracked DB, no IaC/persistent-disk config, boot() blocking ingest, local DB 33 MB that cannot arrive via git). Severity: P0.
Sleep/wake + heavyweight boot on a free-tier host with no warmup/lightweight-readiness path (evidence: 30 s fixed frontend bound, whole-app filtersReady gate, no /api/health-gated degraded UI, "warming up" copy with no warmup architecture). P0.
N+1 DISTINCT years query + middleware COUNT/MAX on every call with no cache (evidence: 21 queries/call measured; statusCache.js memoizes only integrity, not years). Turns a 0.4 s local call into a multi-second call under contention and makes cold paths worse. P1.
Missing global-year covering index (evidence: EXPLAIN shows temp B-tree distinct; idx_observations_ind_year_value can't serve the unfiltered global query). P2 alone, P1 combined with (3).
Frontend years effect without abort + whole-app gate + retry fan-out (evidence: App.jsx:177-196 vs useApi.js:32; filtersReady gating all views; Retry refetches 3 resources). Converts a slow backend into a stuck UI. P1.
4.6 Possible fix directions (for the implementation phase — not implemented now)
Persistent disk / pre-seeded DB artifact for the deployed backend (or documented single-host-with-volume topology); never rely on boot ingest in production.
Boot: listen first, ingest in background; add a cheap readiness endpoint already present (/api/health answers without touching observations — use it for warmup gating).
Cache listAvailableYears in-process with invalidation on publish (same pattern as statusCache.js), and/or collapse N+1 into grouped queries; add covering index on observations(year, …) — must prove byte-identical payloads before/after.
Give the years effect a real AbortController (route through useApi or equivalent), decouple views from the global gate where safe (e.g. Status/DataStatus already independent), stagger bootstrap fetches, debounce Retry.
Do not "fix" by raising the 30 s timeout until the backend answers health+years in well under it on a cold host; a larger timeout without the above only lengthens the outage.

Backend handling is generic and correct (focusIso3 params, FOCUS_COUNTRY single default, unknown → 400). The leak is frontend-side, in four layers:

5.2 Layer A — Active display hardcode in RankMovement.jsx (the observed symptom)
App.jsx:680-696 passes country={effective.country} correctly, and the fetch key is correct (RankMovement.jsx:2871: movement:${metricKey}:${yearA}:${yearB}:…:${basis}:${country} → api.comparisonLevel({…, country})). But the rendered tables ignore the prop:

RankMovement.jsx:626 + :630: <tr className={r.iso3 === 'IND' ? 'row-focus' : …}> + {r.iso3 === 'IND' ? <span> India</span> : null} (main table)
:785 + :789: same hardcode (middle-year table)
:1765 + :1769, :1916 + :1920: same hardcode (interval/growth tables — per subagent extraction)
~40 narrative strings: aria-label="India ranking movement summary" (:138), "India's observed position…", "Above/Below/Crossed India", "Relation to India", "Effect on India's position", filter options Above India in ${a} (:878-902), placeholder="e.g. India, IND, or #12" (:1333), etc.
Every other movement family does this correctly (CapitalMovement.jsx:569,573,742, FxMovement.jsx:542,546,714, etc.: r.iso3 === focusIso + {focusName}). So: changing focus to USA refetches USA data (backend correct) but the Analysis-family movement tables still highlight and narrate India. This matches the reported screenshot behavior exactly and is the primary bug.

5.3 Layer B — Compare defaults coupled to focus (App.jsx:324-326)
const cmpEntityA = … ?? `country:${country}`;
const defaultB = `country:${country === 'USA' ? 'CHN' : 'USA'}`;
Changing global focus rewrites Compare's defaults even if the user never visited Compare; a shared Compare URL without explicit cmpEntity* resolves differently per viewer's focus. Compare.jsx itself is innocent (its depsKey at :466 correctly omits country — the entity specs already encode it — and its fetches send no country).

5.4 Layer C — IND-default + IND-omission URL round-trip (App.jsx:143,314-317,368)
Initial state country:'IND'; invalid/missing → 'IND'; display fallback 'India' iff IND.
Mirror omits country when IND "so existing India links keep working" (:366-368).
Net effect: India is the gravitational default everywhere (correct for legacy links, but any dropped/empty param — including the no-localStorage reload path, since storage grep = 0 hits) silently becomes India rather than an explicit neutral/empty state.
5.5 Layer D — Dormant prop defaults (country='IND', focusName='India' in ~17 signatures)
Overview.jsx:18, Coverage.jsx:13, AuditSource.jsx:13, LevelVerification.jsx:58, YearlyTable.jsx:40, YearComparison.jsx:13, YoyRanking.jsx:26, YoyVerification.jsx:72, FullRanking.jsx:26, all six family movement sections, RankMovement.jsx:51,2852, FocusPicker.jsx:15, MovementCards.jsx:59-60. Currently masked (App always passes explicit values), but any future direct render, test, or new view entry without props reverts to India. FocusPicker's empty-list fallback (free-text ISO3 input) additionally bypasses validation client-side (backend 400s it — safe but rough).

5.6 What is not the cause
Backend focus handling: generic, DB-driven, tested for CHN/USA/IDN + 400s for XYZ/WLD (focusCountry.test.js:11). Not hard-coded beyond the documented FOCUS_COUNTRY default.
Memo staleness: effective deps include filters (hence country) and eligibleCountries (hence focusName updates post-metadata-load) — recomputation is correct.
Cache keys: all section depsKeys include ${country} (48 hits audited); Compare-main intentionally excludes it (entity-spec-keyed). No storage-key leak (no localStorage/sessionStorage usage at all).
main key={dataVersion:view:country} remounts on focus change — this clears stale local state (pagination/tabs), which is correct isolation, not a leak; but it also means focus changes are destructive to in-progress view state (UX cost, §6).
5.7 Capability question
All analysis families accept arbitrary country end-to-end (backend validates any ISO3 in metadata; frontend passes it through; movement LOO uses focusIso3). No family was found with a legitimate India-only limitation — the India persistence is accidental (Layer A) + default gravity (Layers B–D), not methodology.

7. METHODOLOGY AUDIT
All calculations verified against backend/src/domain/ + services/; frontend performs none (confirmed by grep: *100/CAGR hits in frontend are labels/formulas/axis scaling, never economics; chartAdapters.test.js pins exact passthrough with nulls preserved).

7.1 Shared engines (GDP path — approved, must not regress)
Level rank (domain/ranking.js): keep finite-numbered valid rows only (missing never zero/ranked); sort raw value (never formatted) by direction, ISO3 ASC tie-break, 1-based distinct ordinals (not 1,1,3 / not dense) — deliberate total-order choice; denominator = valid observations for that exact metric-year; directionFor returns DESC/ASC/null, null → services refuse RANK_UNSUPPORTED (never silent).
YoY (domain/yoy.js): ((cur/prev)−1)×100 on raw values; guards yield null + reason (never 0): both/previous/current_missing, non_finite, both_years_zero, previous_not_positive, sign_change_across_endpoints; cur==0 && prev>0 validly −100%.
YoY rank (domain/yoyRanking.js): same per-pair rule, order by YoY DESC + ISO3 ASC, own denominator (valid pairs ≤ level denominator).
Universe (domain/universe.js): aggregate iff region.id==NA || region.value==Aggregates || blank ISO3; precedence missing > non-finite > invalid_year > blank_iso3 > aggregate > unknown (catches XD/XN income-group rows).
Level comparison (domain/comparison.js): Common/Exited/Entered ISO3 sets; reuses rank engines; positional above/below (never value compare — tie-break safety); identities commonRankA = fullRankA − exitedAboveA, commonRankB = fullRankB − enteredAboveB, fullB−fullA = (commonB−commonA) + enteredAboveB − exitedAboveA; positionNumberChange = Fb−Fa (down-positive) vs placesGained = Fa−Fb (up-positive); verifyComparison fail-closed → COMPARISON_INVARIANT_FAILED with no numbers on breach; three-year extension with COMMON_3 and per-segment identities.
Growth comparison (growthComparison.js): no cross-interval rank deltas; like-for-like universes G(AB) / G(AM)∩G(MB)∩G(AB); unweighted peer mean (focus excluded, ISO3-sorted sum); vsPeer plain pp subtraction; flow endpoint labelled Annual flow: B vs A.
Transforms/periods (transforms.js, periods.js): capability-gated (canTransform); percentChange ≡ YoY for valid inputs; CAGR needs years>0, A>0, B≥0; group SUM strict, group ratio recomputed from legs (never averaged); cross-rate A_per_USD/B_per_USD; canonical period is half-open [A,B) with strict completeness (INCOMPLETE_PERIOD + missing list, never zero-filled/silently skipped).
Coverage (domain/coverage.js): CASE B>C>A>D facts-only with forbidden-phrase test pins (never invents missing-data causes); separate YoY coverage.
Format (domain/format.js): presentation only (T/B scale hints, decimals).
