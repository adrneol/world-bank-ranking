PART B — FLOW METHODOLOGY (the core 7C design decision)
Status quo (verified): there is no period aggregation anywhere — PERIOD_SUM has zero hits in backend/src; 7B's flowSemantics.periodRule is an honest denial ("No PERIOD SUM is computed"). Every multi-year flow comparison is ((flowB/flowA)−1)×100 on two endpoints, interiors ignored. 7B made the label honest ("Annual flow: B vs A") but did not create the missing statistics. The manual-testing complaint is therefore sustained: FDI 2004→2014→"+536%"-style output answers almost no economic question, and 2004→2015 currently means ((flow2015/flow2004)−1)×100 — two observations out of twelve.

Recommended design (three distinct, never conflated):

ANNUAL_FLOW_ENDPOINT (exists, keep, keep label): B vs A with abs + valid % — answers "how did the annual flow in B differ from A". Valid for all 5 flows (+ reserves/population as stock endpoint change). UI: current "Annual flow (endpoint B vs A)" label. This is the secondary mode for multi-year spans.
PERIOD_FLOW_SUM (new, PRIMARY for multi-year flow spans): S(P) = Σ flows over the period, completeness rule = every year present else unavailable + member/year coverage attached (reuse groupSum strictness philosophy: never zero-fill, never interpolate). Period-vs-period change compares two sums with abs + % (guard: zero/negative base → reason, same engine as signed flows).
PERIOD_FLOW_AVERAGE (new, companion): S(P)/N — answers "typical annual scale"; same completeness rule.
Interval rule — half-open [A, B), proof: adjacent decade comparison must partition the timeline without double-counting the boundary year. [2004,2014) + [2014,2024) = years 2004…2013 and 2014…2023, disjoint and covering 2004…2023 exactly. Inclusive-with-non-overlap-rule is expressively equivalent but pushes boundary bookkeeping onto every caller and every test; half-open makes adjacency composable by construction and matches the existing completeness machinery (a missing year fails the range query either way). Explicit rule: endpoint ops use exactly {A, B}; period ops use [A, B); therefore user selection 2004→2015 = 11 annual observations (2004…2014) — documented in UI copy and methodology strings, with the count echoed in the response (periodYears: [2004…2014], periodSize: 11). Missing year → unavailable + reason + coverage, never zero-fill. Default for FLOW movement over spans > 1y: period-total comparison; annual-endpoint retained as a separate explicit mode. LEVEL/stock metrics keep endpoint semantics (GDP untouched by construction — new transforms gate on FLOW).

Per-flow notes: exports/imports/remittances (POSITIVE_ONLY) — sums/averages straightforward. FDI/CA (SIGNED) — sums valid (net position over period is meaningful), % change on sums needs base-guard; negative-period-sum change reported as absolute + reason, never a sign-flipped %. Never sum ratios (FDI% stays pp-only; group ratio via leg resolution, see Part F).

PART I — CHART AUDIT
Inventory: exactly 2 visual encodings — hand-rolled SVG TrendChart (sole caller: Compare Trajectory) + CSS partition/duo readouts (content-width, not proportional — must never be mistaken for bars). Everything else is tables/cards. No log scales, no canvas, no sparklines.

Use-case map: long series → line (linear, gaps break, titled, sourced); 2-endpoint change → slope/dumbbell, never a 2-point "trend line"; annual flows → bars/line; period totals/coverage → proportional bars; inflation → rate line + pp annotation; real-GDP+inflation → stacked small multiples sharing x (never one axis for % and $); rank movement → slope with rank 1 on top; country-vs-group → bars/dumbbell (SUM-only); disparity → small multiples/indexed, never silent log.
Library: Recharts. React 19 + zero chart deps today; Recharts v3 (React-19-compatible) covers every type above declaratively (dumbbell = Scatter+Line, dual-unit = ComposedChart — though small multiples preferred), ~130–180 kB gz, SVG-DOM accessibility matching the app's table-first a11y, ResponsiveContainer mobile story, and single-chart incremental migration (Trajectory first). ECharts rejected (250–400+ kB, canvas a11y weaker, wrapper lag, glossy-theme rework). Hand-rolled extension rejected (niceTicks rounding debt already shows the maintenance curve). Do not install until approved.
PART J — PYTHON vs NODE: KEEP NODE. Do not add Python.
(a) All visualization is presentation of backend-finished numbers — React + Recharts covers it.
